# Complete Error Message Audit

## Problem

The first error-reason patch repairs the authoritative/worker path but its remaining-audit categories are too broad. Several listed omissions can be fixed without protected interfaces, while true enum/unit/nil information loss needs distinct producer-side work. These must not be conflated with permission blockers or intentional cancellation.

## Decision

Produce an exact inventory of every remaining confirmed loss from the two existing audit scopes: source function/line, lost information, current user surface, prior reason for leaving it, minimal safe repair and actual spec approval scope. Complete bounded existing-interface fixes with meaningful narrow tests, including special read mapping, available typed asset ledger projection, safe source forwarding and known native account classification. Preserve current top-level codes, blocking, retry, cancellation, ownership and data behavior. No real graph or Simulator operations in this follow-up. Protected spec and Dune files remain unchanged.

## Alternatives considered

### Classify every remaining item as intentional hiding

Rejected: a known safe typed reason being erased is a reporting defect; privacy only forbids raw content, not finite cause categories.

### Expand all protected interfaces immediately

Rejected: AGENTS requires an explicit request to modify OCaml under spec/. Show exact proposed field/signature changes first when no existing path preserves the cause.

## Acceptance criteria

- Each remaining source from the earlier inventories has an exact disposition, with neither vague deferral nor false permission blockers.
- Small existing-interface fixes have demonstrated failing then passing behavior at their actual owner, without redundant new CI targets.
- Existing relevant tests pass; current source and prior6504 runtime evidence are distinguished.
- No real graph/DB/account, Simulator, protected spec, Dune, PR or release operation occurs.

## Risks

- Native Boolean/nil callbacks and asset enums may require genuine protocol/producer work; a list is not an implementation.
- Unknown external source text must remain a bounded safe summary, never raw body/credential/path content.

## Questions

- None for the bounded follow-up. Explicit permission for any protected spec change must be sought with its exact scope; no such change is assumed authorized.
