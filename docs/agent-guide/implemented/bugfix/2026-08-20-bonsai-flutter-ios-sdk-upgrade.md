# Bonsai Flutter iOS SDK Upgrade

## Problem

The repository manifests and lockfiles refer to different historical
`bonsai_flutter` revisions, while the installed host packages and iPhoneOS SDK
use the repository generated for SDK package `0.1.0~dev.11`. This prevents a
fresh checkout from reproducing the host and device builds and can hide source
and SDK protocol mismatches.

## Decision

Pin both application packages and their lockfiles to the SDK repository commit
`a6bd9aa9906c0e49f0cc365e5ba33270e89655e6`, synchronize the generated Flutter
host against that tool version, and adapt application-owned code to the current
public APIs. Verify the OCaml, Flutter, macOS, and unsigned iOS build paths with
the installed iPhoneOS toolchain.

Use `a6bd9aa9906c0e49f0cc365e5ba33270e89655e6` as the single host package pin
across both package manifests and lockfiles. Consume the opaque
`Sparse_extent_transition.t` through its public accessors. Keep the generated
Flutter host unchanged because synchronization confirms it already matches the
updated CLI.

## Alternatives considered

### Pin the framework source commit directly

Pinning `108b8b50977c7ff4933f6cd6e84bf2e4b4de15c6` would select the framework
source used inside the SDK, but it predates the generated SDK repository commit.
The host CLI is intentionally installed from the regeneration commit so it can
discover and verify the matching `0.1.0~dev.11` repository metadata.

## Consequences

Fresh host installations and the checked-in iPhoneOS dependency lock now select
the same SDK repository generation. Tests no longer depend on the removed public
record representation of sparse extent transitions. Older framework and SDK
repository revisions are intentionally rejected by the source-boundary test.

The repository intentionally drops compatibility with older `bonsai_flutter`
protocol and SDK revisions. Full platform builds depend on the locally installed
Flutter and Xcode toolchains and may expose host-project changes generated by a
future CLI.

The implemented revision passes OCaml and Flutter tests, host synchronization,
the macOS debug build, the unsigned iOS debug build, and iPhoneOS toolchain
verification for SDK package `0.1.0~dev.11`.
