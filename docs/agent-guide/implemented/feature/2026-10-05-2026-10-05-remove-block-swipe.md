# Remove Journal block swipe actions

## Problem

Journal block rows still expose horizontal swipe actions after long-press context menus replaced them. The user requested removal of all block swipe content.

## Proposal

Remove Journal-owned swipe descriptors, serialization, callback registration, SwiftUI swipe modifiers, and obsolete row-swipe tests and documentation. Keep Timeline Change status and Delete context menus, Favorites navigation, Detail Open/Delete menus, and shared mutation, undo, status-sheet and notification-dismissal behavior. Rename the still-used status-sheet palette to describe its current use. Do not modify LUI or protected Dune/spec files.

## Decision

Implement the proposal within Journal, preserving existing business actions and shared APIs. The user explicitly authorized this scope.

## Alternatives considered

### Hide the controls only

Rejected because unused adapter fields, action callbacks and stale documents would remain.

## Acceptance criteria

- Mounted production Timeline/Favorites rows carry context menus without swipe payloads; retired swipe action keys do not dispatch.
- Mounted Detail leaf/disclosure rows carry context menus without swipe payloads; row-scoped Open/Delete events still work.
- Disabled, hidden, malformed and unmounted menu actions remain fenced by existing public boundary tests.
- Formatting, compilation, related tests and the full suite pass; simulator/manual limitations are reported honestly.

## Consequences

Journal block rows expose their supported actions through context menus. Shared Delete/Undo/status mutations and notification dismissal remain; shared LUI APIs are unchanged. Production mounted regression tests reject swipe payloads and retired action keys while preserving supported menu events.

## Risks

- Historical mixed-purpose decisions must retain unrelated Capture, status, navigation and rendering requirements.
- Notification swipe dismissal and vertical scrolling are independent of block actions and remain supported.
- The pure Application reducer owns business mutations, but native gesture configuration and extension callback binding are owned by the mounted Native_list wrapper. Regression tests therefore use the public mounted LUI protocol boundary, supplementing existing reducer coverage without duplicating mutation tests.

## Questions

None. The user's explicit request settles removal scope and retains long-press business operations.
