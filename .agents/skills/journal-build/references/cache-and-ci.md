# Cache, recovery and CI measurement


Identity includes source, actual dependency ABI inputs, toolchain/SDK, flags and target. Identical inputs reuse incremental state; changed inputs select another namespace. Native runs preserve a Dune process trace for actual compile/link observations. Every run leaves external phase logs and `run-*/manifest.json`. The cache has a nonblocking lock; native Dune builds also hold the switch read lock. A busy lock belongs to its active owner: coordinate or wait. Preserve existing output/rollback apps and choose a new `--app-dir`; nothing is cleared automatically.

Producer-only and the native macOS App path share native incremental state for identical inputs. A warm producer reads the current Dune rule and revalidates the immutable evidence and live inputs before reuse; an existing cache directory alone is not a hit. Keep measurements on one source revision, explicit switch/compiler/SDK, configuration and absolute paths. For a cold sample, use a new owned external cache; never clean shared dependencies. Record actual compiler/link actions and separate phase/end-to-end elapsed time from resource or authorization waits. A failed macOS App attempt is not a successful App baseline: report its failed phase separately and compare final Simulator success only when both routes reach it.

For failure, read `failed_phase`, `error` and that phase's log. Correct target/environment or select matching prepared inputs. Source/configuration/pin/current-input mismatch requires matching provenance; a historical archive change alone can use the validated receipt contract above. Missing runtime/mldoc or unresolved XMLm references require linker-rule review. Schema 2 permits an unused XMLm unit to be omitted while retaining strict locked input identity; schema 1 keeps its original force-link checks. Protected Dune/spec/lock edits still follow the repository's authorization rules. Legacy object-injecting Dune aliases remain refused; probe helpers use the isolated mode above.

## Reuse dependency and build state

The Apple builder consumes a prepared switch; it neither provisions it nor manages GitHub caches. Reuse its existing `run-*/manifest.json`: `inputs.toolchain.opam_prefix` is the canonical absolute switch prefix, `ocaml`/`compiler_sha256` identify its compiler, `inputs.dependencies` records checked lock versions, resolved pins and native library hashes, and `cache_key` selects the incremental Apple workspace. Re-run preflight against the same explicit inputs before building. A matching directory name or a previous `cache_reused: true` does not replace those checks. Do not relocate a switch, copy large caches between worktrees, change global pins, or mix macOS/Simulator/device objects to obtain a hit. Retain final input verification, full build/tests and the target acceptance limits above.

CI dependency caching belongs to `.github/workflows/ci.yml` and `.agents/skills/journal-build/scripts/prepare_ci_dependencies.py`. The workflow first installs the native Homebrew inputs (GMP, SQLite, zlib, zstd and pkg-config), selects their explicit pkg-config directories, and resolves locked Git pins once. `--cache-identity` then records `.ci-reports/opam-cache.json` **before setup creates a compiler or switch**. No installed compiler or opam command is needed for this lookup.

The `journal-opam-v4-<OS>-<arch>-<family>-<native>` key separates compatibility from native-provider observations. The family binds exact OCaml package and pinned opam-repository recipes, expected opam version and pinned setup action, lock/manifests and resolved Git SHAs, absolute workspace/switch/root prefixes, native OS major/architecture, selected Xcode/SDK/clang, effective build-tool paths/bytes and compilation flags. A changed effective `cc` still changes the family; an extra empty PATH directory does not. Environment values are hashed in reports. Runner ImageVersion, OS patch/build, full PATH digest and unrelated workflow/helper comment bytes do not determine compatibility. Increment schema_version deliberately when the bootstrap contract changes. `CI_OPAM_VERSION` is an expected version check, not a downloader selector; the pinned setup action controls its release selection, and an unexpected opam version fails sealing. The Apple builder's compiler binary hash and native artifact provenance remain strict and unchanged.

The native suffix records current GMP, SQLite, zlib and zstd versions, pkg-config flags, selected headers and libraries. Request an exact variant first, then allow prefix restoration **only within the same family**. Restore the complete `$GITHUB_WORKSPACE/_opam` and `~/.opam` before setup-ocaml, with setup's overlapping caches disabled. A matching switch receipt and compiler/switch metadata hashes are required before the restored compiler is run. Native and bytecode compiler smoke builds must pass before setup reuses the switch. A missing archive, invalid receipt or unusable compiler selects a clean setup; only exact disposable hosted-runner paths may be quarantined. No compiler/SDK/lock/path fallback is allowed.

A different SQLite version or archive hash does not itself reinstall anything. After setup, exact re-pinning and depext checks, `--check-native-cache` examines installed C stub undefined symbols and actual Mach-O install-name providers, asks dyld to resolve required symbols in both current and linked providers, and compiles/runs the existing SQLite binding in native and bytecode modes (WAL, foreign keys, prepared statements and blobs). Zarith also runs big-integer arithmetic through both modes. Compatible bindings remain untouched. Failed binding/link probes select only their installed owner packages (for example sqlite3), and `opam reinstall --locked --ignore-pin-depends --yes ROOTS` computes their reverse dependency closure. Empty roots never invoke reinstall. Unidentifiable owners or failed post-repair probes fail the job. SQLite 3.x is not a blanket compatibility promise: a downgrade missing a required symbol is incompatible. Runtime/link checks cover the installed dependencies and full source regression covers application behavior.

The helper test step clears its ambient `PKG_CONFIG_PATH` because Apple CLI fixtures require explicit tool selection; the CI identity fixture supplies its own native providers, and other workflow steps retain the selected CI providers. The ordinary locked install, helper boundary tests, `dune build @all app/native_embed.exe.o` and full `dune runtest --force` stay unconditional. Sealing reobserves family/native inputs, repeats native probes, and checks actual compiler configuration/version/architecture, absolute prefix and opam version. Changed final inputs cannot be saved. A validated fallback is recorded as `source: compatible`, not an exact Actions hit; a successful different native variant is saved under its new immutable key. Corrupt exact entries cannot be overwritten; bump the namespace for an authorized contract repair or request deletion of only that identified cache. Never clear shared caches or alter another owner's switch/pins.

`cache-restore.json` and CI logs distinguish no accessible archive, family input mismatch, receipt/hash rejection, compiler probe failure, compatible native changes and selective repair. Each known difference reports its field, cached/current values and decision. Audit-only changes are explicitly ignored. A separate tiny data-only `journal-opam-input-v4-` record may restore across families to explain misses; it never authorizes executable restoration. If no readable prior manifest exists, logs show current inputs and `comparison_available: false`, without guessing a cause. Redact personal home names and hash environment values. GitHub default/base/current-ref visibility and immutable archive versions still apply; sibling PR merge-ref caches are isolated.

The workflow cancels an older run only when a newer `pull_request.synchronize` head enters the same workflow/PR concurrency group. Main and controlled comparison runs have unique groups. No manual cancellation or repository settings change is needed.

### Measure cold and hot CI runs

Run this experiment only when publishing/rerunning CI is authorized. The local lightweight checks do not measure remote cache effectiveness. Use a new cache namespace for a cold run of one exact revision; complete the job successfully so the dependency cache is saved. Then rerun that same run/revision once, with no workflow/source/dependency changes. Do not delete an active owner's cache or use another owner's worktree.

```sh
# First select the completed, authorized cold run; this command only lists runs.
gh run list --repo logseq/logseq_journal --workflow ci.yml --limit 10
COLD_RUN_ID=REPLACE_WITH_COLD_RUN_ID
# Execute the hot measurement only after authorization; this triggers CI.
gh run rerun "$COLD_RUN_ID" --repo logseq/logseq_journal
gh run watch "$COLD_RUN_ID" --repo logseq/logseq_journal --exit-status
# Keep evidence outside the repository. Reruns increment attempt numbers.
EVIDENCE_DIR=/absolute/external/evidence/ci-cache
mkdir -p "$EVIDENCE_DIR"
gh run view "$COLD_RUN_ID" --repo logseq/logseq_journal --attempt 1 --log > "$EVIDENCE_DIR/cold.log"
gh run view "$COLD_RUN_ID" --repo logseq/logseq_journal --attempt 2 --log > "$EVIDENCE_DIR/hot.log"
gh run download "$COLD_RUN_ID" --repo logseq/logseq_journal \
  --name journal-ci-evidence --dir "$EVIDENCE_DIR/hot-artifact"
```

Save each attempt's `journal-ci-evidence` artifact immediately after it completes (including the cold artifact before rerunning); it contains `dependencies.json`, `opam-cache.json`, `cache-restore.json`, `cache-receipt.json` and `packages.txt`. Select the real attempt numbers if not 1/2. Compare the identity JSON/key, resolved SHAs, image/version, compiler, absolute prefix and installed package lists. A changed family or absent restored archive is a cold sample. For a compatible native variant, record the matched/requested keys, `source: compatible`, actual provider/runtime versions, required-symbol results and unchanged compiler/stub hashes; do not label it an exact Actions hit. Record setup/bootstrap, system-dependency preparation, restore, re-pin, locked-install elapsed time and installed/recompiled package counts, final build/test time, cache save time and total job duration. Count setup/compiler cost as well as dependency-install cost; strict matching may trade hit rate for correctness. Keep full build/tests in both attempts. Report measured seconds and counts; do not infer a saving percentage from the earlier two runs, which both installed 170 packages despite a root-cache hit.

### Controlled native-provider comparison

When explicitly authorized, a temporary push workflow on the owned branch can call this same workflow twice sequentially with `workflow_call` input `sqlite-profile: '3.50.4'` then `'3.49.2'`. `prepare_ci_sqlite.py` downloads checksum-pinned official SQLite amalgamations and compiles them into the same disposable `RUNNER_TEMP/journal-ci-sqlite` prefix/install name. The second profile also prepends an empty PATH directory. It never installs into Homebrew or a user switch. The binding runtime must report the requested provider version in these fixture runs, so a pkg-config-only change cannot pass as a real experiment. Keep both full builds/tests, compare actual compiler/stub bytes and all opam installation actions, then remove the temporary caller and require green normal PR CI on the final head. The reusable workflow remains the single build/test implementation. Evidence belongs outside Git.
